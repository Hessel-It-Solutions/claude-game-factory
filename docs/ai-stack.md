# The AI stack: Claude Code, Codex and Runway

The factory uses three AI tools, and each one has a job. Mixing up the jobs was the most expensive mistake of the first game, so this page explains who does what and why.

| Tool | Role | Paid with |
|---|---|---|
| Claude Code | Producer and director. Plans waves, talks to you, writes briefs, reviews diffs, measures results, integrates batches, runs the gates. | Claude subscription (tokens) |
| Codex CLI | The engine. Writes Godot code and tests, generates sprite pose strips through sprite-gen, edits images, and can run long blind playtests. | ChatGPT subscription (Codex quota) |
| Runway (MCP) | Art and audio generation: identity bases, portraits, key art, storyboard illustrations, painted rooms, music, SFX, voice, and locomotion video when a sprite needs it. | Runway credits |
| Godot 4 | The game engine. GUT for unit tests, headless scripts for bots and captures, Android export. | Free |

## Claude Code: plan, review, integrate

Claude Code runs the `/game-factory:game-factory` command and reads the `gf-producer` skill, which is the contract every other skill follows: folder layout, file ownership, gates, wave map, budget rules.

What Claude does well here, and what it should keep doing:

- Interview you in pre-production, present options side by side, record decisions.
- Turn a playtest report into a short list of fixes, each with acceptance criteria you can measure.
- Write a brief for Codex, then read the diff Codex returns, run the full test suite and the bot on the main tree, and look at real captures before accepting anything.
- Diagnose when Codex keeps failing at the same problem. In the David project an Opus subagent, read-only, found the root cause of an unstable bot with file and line, and Codex then implemented the fix.

What Claude should not do: write large amounts of game code or grind sprites in parallel subagents. In one wave six Opus subagents in parallel used about 2.5M tokens on Godot code, painting and sprites, most of a week's quota, for work Codex could have done on a different subscription.

### Subagents

- Always pass an explicit `model`. Leaving it out inherits the session model, which may be the most expensive one.
- `sonnet` by default. `opus` only where reasoning pays for itself: GDD, script, continuity review, architecture, hard diagnosis.
- Few agents. Each one starts from zero and pays again for the shared reading. Group work by chapter or role, not by item.
- Paste the minimum context into the prompt (`tools/gf/gf.sh context <role>` builds it). Never tell a subagent to "read the bible".
- Continue an agent with a follow-up message instead of opening a new one.

## Codex CLI: the engine

Codex does the volume: code, tests, sprite strips, image edits. Things we learned running hundreds of `codex exec` batches:

- Always run `codex exec ... < /dev/null`. Without it Codex waits on stdin ("Reading additional input from stdin") and sits there. We lost two hours to this once.
- Options go before the subcommand: `codex exec -s workspace-write -o out.md resume --last "..."`. `resume` re-reads the whole session, so cost accumulates.
- Briefs are short lists of acceptance criteria. A long prose brief comes back half done with green tests.
- Run parallel batches in isolated copies of the project. On macOS `cp -cR` makes an APFS clone that costs almost no disk; `tools/codex/batch_launch.sh` does this. Merge per file against a baseline afterwards and delete the clones (one folder reached 348 GB before we added that rule).
- Codex has no display inside its sandbox, so window captures and Android export run in the main session.
- Codex playtests need network access for adb: `-c sandbox_workspace_write.network_access=true`.

### Never trust a Codex report without measuring

Every one of these happened at least once:

- It reported a wall "with no gap" that had a gap.
- It wrote a test that passed without the player moving.
- It reported a bot run of 33/33 that did not reproduce three times in a row.
- It delivered an old capture copied from the cache as a "new" one.
- It changed the scenario bot so the bot would pass, hiding a real regression.
- It wrote GUT tests that only read the source code with `assert_string_contains`.
- It copied the English text into the Portuguese and Spanish columns, and the test only checked "not empty".
- It undid an old fix while "fixing" something else, and changed the old test to match.
- It changed a global rule when the brief asked for one enemy.
- It edited a JSON file that is generated by a tool, so the next build overwrote the change.

The checklist in [`tools/codex/README.md`](../plugins/game-factory/tools/codex/README.md) exists because of this list: diff the whole batch, run the full suite on main, compare the bot against the baseline, reject tests that only read source, and look at the captures yourself.

## Runway: art and audio

Runway is connected as an MCP server (in Claude Code through claude.ai connectors or a local MCP config). The `gf-runway` skill is the manual: which model for which asset, how to keep identity with reference images, how to download results and record the cost.

- Before any wave that generates art, video or audio, the producer estimates credits per item and shows you the number. Above 300 credits, or any batch of video, it waits for your approval.
- Check the balance before and after each wave (`whoami`) and log it in `production/BUDGET.md`.
- The hybrid model that worked: concepts, turnarounds, sprites and most storyboard frames through Codex (subscription, no credits); Runway only for identity bases, portraits, key art, painted rooms, illustrations and audio.
- Prompts with the word "boy" in a sound effect request were blocked by moderation (it flags them as involving children). Describe the sound, not the person.
- `list_recent` dumps very long URLs into the context. Download results with `get_task` from a small subagent instead.
- Background removal (`remove_image_background`) is cheap and works well to cut a character out of a storyboard frame enlarged 8x. It fails on very small objects; failed calls are refunded.
- Calling Runway from a subagent can be blocked by the permission classifier. Do not work around it: generate from the main session.

## Cost control rules

These came from real budget overruns:

1. Before every wave, show three estimates per item: Runway credits, Claude tokens, Codex tokens. After the wave, show the real numbers.
2. Mechanical work (registering assets, slicing sheets, building boards, moving files) goes to `tools/gf`, never to an LLM and never to a one-off script.
3. For visual tuning (scale, color), measure and build a comparison board first, then send Codex only the parameter you chose. Scaling sprites by trial and error through Codex took five rounds and about 1.7M tokens.
4. Do not review, draw or storyboard chapters that are not going into production now. Gate G3 can cover a pilot only.
5. "Stop" means stop now: every agent and every `codex exec` and `sprite-gen` process the session started. Do not `pkill -f codex` blindly: it also kills the ChatGPT IDE extension and anything else with `.codex` in its path.
